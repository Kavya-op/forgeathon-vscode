2. Starting point

Built from scratch using a clean, modular editor-native architecture conforming to the official Model Context Protocol (MCP) 2024-11-05 specification and the Visual Studio Code Extension API. Zero proprietary agent-loop retention was used; the implementation strictly relies on the local TrueForge agent harness (@truefoundry/trueforge) for all planning, multi-turn tool loops, and execution lifecycle management.

3. Architecture on TrueForge

The system establishes a clean, decoupled boundary between editor presentation and autonomous agent execution:

  • Client Communication & Streaming: The VS Code extension connects to the local TrueForge harness via HTTP and Server-Sent Events (SSE) at /api/v1/sessions and /api/v1/sessions/:id/turns. Real-time delta tokens stream directly into the active editor/panel webview without blocking the UI thread. An AbortController signal is wired to Esc and Cancel buttons to abort turns instantly without leaving dirty files.
  • Editor Capabilities Exposed as MCP Tools: The extension hosts an in-process JSON-RPC 2.0 stdio MCP server exposing 6 tools: read_file (line-budgeted file access), search_workspace (filtered regex workspace search), get_symbol_definitions (AST and decorator symbol lookup), propose_diff (unified diff hunk generation), run_terminal_command (isolated shell execution), and assemble_context (scored file selection).
  • Harness Features Utilized: (1) Human-in-the-Loop Tool Approval: In agent.json, propose_diff is configured with "approval": "always_ask", requiring explicit interactive approval before any disk write. (2) Context Compaction: Configured with structured_summary triggering at 24,000 tokens to prune history to a 16,000 target budget. (3) Resilience & Multi-Model Routing: Automatic failover switches to secondary endpoints if the primary endpoint becomes unreachable.

4. How context is selected

Operating on large codebases (such as pallets/flask at ~17,000 lines) requires budgeted, multi-stage retrieval rather than dumping raw repositories into context:

  • Explicit Mentions: @file and @symbol identifiers are resolved with highest priority.
  • Size Budget Constraints: Maximum 12 context files; maximum 4,000 tokens per file; maximum aggregate retrieval budget capped at 16,000 tokens.
  • Task Role Heuristics: Keyword analysis categorizes candidate files across functional roles: CLI registry (cli.py), test validation (test_cli.py), and documentation (cli.rst).
  • Rationale Logging: For every selected file, the agent emits an explicit selection rationale shown in the UI during Task B (e.g., "src/flask/cli.py → Primary CLI registry where built-in click commands are defined").

5. Model setup

  • Primary Model: Gemini 2.5 Flash / Claude 3.5 Sonnet (OpenAI-compatible endpoint via Google AI Studio / TrueForge gateway). Hosted API; total cost < $0.05 for all test runs.
  • Secondary Fallback Model: Gemini 1.5 Flash / GPT-4o-mini (hosted OpenAI-compatible endpoint) and local Ollama (qwen2.5-coder:7b).
  • Model Switching: Configured centrally in agent/models.json with zero extension re-compilation. Primary and fallback tiers switch automatically upon connection failure or rate limits.

7. Tools used

  • Agent Harness: TrueForge (@truefoundry/trueforge) running in local mode on localhost:8790.
  • Integration Protocol: Model Context Protocol (MCP) JSON-RPC 2.0 stdio server.
  • Host Environment: Visual Studio Code Extension API (v1.90.0+).
  • AI Assistants: LLM coding agent used for project scaffolding and unit test verification (declared per rule 4; costs no points).

8. Known limitations and what you would do with another month

  • Current Limitations: (1) Semantic symbol lookup currently relies on regex pattern matching and AST heuristics rather than an incremental vector embedding index. (2) Multi-file diffs in Task B are presented sequentially per file rather than in an integrated multi-tab split grid.
  • What We Would Do With Another Month: (1) Integrate Tree-sitter for language-agnostic semantic code graph navigation across languages. (2) Leverage TrueForge's native Daytona container sandboxing to run test suites in isolated microVMs. (3) Implement three-way merge resolution for concurrent hunk conflicts across large refactoring tasks.
